# 釣果海図ログ

海図（地理院タイル＋OpenSeaMap航路標識）の上に、釣果（位置・魚種・棚・締め方・気象・潮汐・波浪）を記録するWebアプリです。
等深線と推定水深は GEBCO_2026 Grid から作っています（日本周辺、1度×1度の区画ごと）。
「おすそわけ」タブでは、釣りすぎた魚を無料で譲る相手や、魚介類販売業の許可を持つお店とつながれます（富山県内のみ・Supabase を使用）。
「みんな」タブでは、釣った魚や料理の写真・ブログを載せて、いいね・コメント・メッセージでやり取りできます。

## 使える人と機能

| | ログインなし | ログイン（無料） | 会員 | 管理者 |
|---|---|---|---|---|
| みんなの投稿を見る | ○（釣った位置は見えない） | ○（釣った位置は見えない） | ○（釣った位置も見える） | ○ |
| いいね・コメント・メッセージ | — | ○ | ○ | ○ |
| 釣果・航跡の記録、おすそわけ、写真・ブログの投稿、PCとスマホの同期 | — | — | ○ | ○ |

- 会員は、管理者が「管理」→「利用者と会員」で「1年間の会員にする」を押して決めます（決済の仕組みを入れるまでの方法）。期限の翌日から無料の扱いに戻ります
- 会員でなくなっても、端末に保存済みの釣果は「釣果一覧」で見られ、バックアップもできます
- 「みんな」の投稿の釣った位置は、会員だけが見られます（投稿した本人は自分の分を見られます）
- 地図の上の中央に現在地の緯度経度（度分表示と精度 ±m）を出します。押すとその場所へ移動します。GPSのないPCでは数kmずれます
- 右上の自分の名前のボタンから、アイコン（正方形に切り抜いて256px）と表示名を変えられます。アイコンがない人は表示名の1文字目を丸で表示します（avatars バケット・誰でも見られる）
- 航跡：線の色と太さを選べます。色は途中で変えると、それ以降の線だけが変わり、記録済みの色は残ります（区間ごとにまとめて変えることもできます）。アプリを閉じていたなどで2分以上記録が途切れた区間は点線で表示します
- 航跡の線の色は「色の決め方…」で「日ごとに自動（8色を自分で決められる）」か「いつも同じ色」を選べます。変えても記録済みの航跡の色は変わりません
- **PCとスマホの同期（会員）**：ログイン中は、釣果（写真は除く）と航跡を自動で同期します（開いたとき・保存したとき・裏に回したとき）。同じ記録を両方で直したときは、あとから直した方が残ります。消した記録はほかの端末でも消えます。写真は「釣果一覧」の下の「写真を同期（手動）」を押したときだけ送り・取り込みます（本人だけが見られる cloud バケット）
- 会員でない端末やログインしていない端末では、これまでどおり「JSONバックアップ」→もう一方で「復元」で移せます
- メッセージは、投稿を開いて「メッセージを送る」から始めます。やり取りは「みんな」→「メッセージ」に並びます

## フォルダ構成

```
index.html            アプリ本体
tiles/index.json      区画の一覧
tiles/36_137.json     等深線（北緯36〜37度・東経137〜138度）
tiles/36_137.bin      水深格子（推定水深用、241×241 Int16、陸は -1）
tools/build_tiles.py  GEBCOのGeoTIFFから tiles/ を作り直すスクリプト
supabase/schema.sql   おすそわけ・お店の機能用のサーバー設定（Supabase の SQL Editor で実行）
```

区画名は「南端の緯度_西端の経度」です。

## 動かし方

`index.html` をダブルクリックで開くと、記録はできますが等深線は出ません（ブラウザがローカルファイルの読み込みを止めるため）。
次のどちらかで開いてください。

### PCで試す（ローカルサーバー）

このフォルダで次を実行し、ブラウザで http://localhost:8000/ を開きます。

```
python -m http.server 8000
```

### スマホでも使う（GitHub Pages）

1. GitHubで新しいリポジトリを作る
2. このフォルダの中身（index.html と tiles/ など）をそのままアップロード
3. Settings → Pages → Branch を `main` / `(root)` にして保存
4. 数分後に表示される `https://<ユーザー名>.github.io/<リポジトリ名>/` を開く

## おすそわけ・お店の機能（Supabase）

設定しなくても釣果の記録・航跡・等深線はこれまでどおり使えます。「おすそわけ」タブだけが「設定が必要です」と表示されます。

### しくみ

- **おすそわけ**：無料。取りに来てもらう対面渡しだけ。受付は釣った日のうち。1人1日5件まで
- **お店向け**：魚介類販売業の許可を持ち、管理者が承認したお店だけが見られ、申し込めます。支払いはアプリを通さず当事者間。1人1か月4件まで
- 出品は「24時間以内に写真つきで記録した自分の釣果」から選ぶ形だけ。釣った位置は本人と管理者だけが見られ、ほかの人には受け渡し場所が約1km単位で表示されます
- アワビ・ナマコ・サザエ・イセエビ・ウニ・貝・海藻・エビ・カニ・ホタルイカ・タコ・フグなどは出品できません（管理画面で追加・削除できます）
- 受け渡し場所と時間は、申し込み後のメッセージで決めます
- **取り消し・取り下げの理由**：申込者の取り消し（受け渡しで魚を見てやめる場合も）と、出品者の取り下げでは理由を選び、相手のやり取りに自動でお知らせが出ます。受けた・見送った・受け渡し完了などもお知らせが出ます。自分で取り消した申し込みは、申し込み直せます
- **連絡先カード**：電話番号・LINE ID・住所・時間帯を「やり取り」の上に保存しておき、申し込みが決まった相手にだけ送れます。相手から見えるのは取引中と、受け渡し済みから3日間だけです
- **お店の買い取り希望**：承認済みのお店が「魚種・サイズ・締め方・処理・価格・地域・期限（60日以内）」を出せます（受付中は10件まで）。釣り人は「探す」で見られ、条件に合うお店向けの出品は、そのお店の「探す」で「希望に合う」と表示され先頭に並びます
- **出品の編集**：受付中の出品は、匹数・大きさ・締め方・締めた日時・処理・保冷・受け渡し場所・価格・ひとことを直せます（魚種・釣った日時・写真・位置は変えられません）。申し込んでいる人には変更のお知らせが届きます
- **締めた日時**：日付つきで入力します。「釣った日時」には開いた時刻が入るので、あとから登録するときは「30分前」「1時間前」などのボタンや写真の撮影日時で直します。締めた日時が釣った日時より前・未来になっていると、その場で知らせて直すボタンを出します
- **相互評価**：受け渡し済みの取引を、30日以内にお互い1回ずつ3項目×5段階で評価します。平均は3件以上たまってから表示します。ひとことは管理者だけが見られ、不当な評価は管理画面から消せます
- **電話番号（SMS）の認証**：管理画面のスイッチをオンにすると、おすそわけの出品・申し込みの前に1回だけ携帯電話番号の認証が必要になります（最初はオフ）。1つの番号で1アカウント、日本の携帯（070・080・090）だけ。番号はほかの利用者に見えず、「認証済み」の印だけが出ます。利用停止した人の番号は、作り直しても認証できません（番号は元に戻せない形でだけ保存）。管理者は「電話の認証を外す」で解除できます
- 通報 → 管理者が出品の削除・利用停止
- **みんな（写真・ブログ）**：写真は6枚まで、1日20件まで。釣果の記録を選ぶと魚種・大きさ・写真が入ります。「釣った位置を載せる」を選んだときだけ位置を保存し、ログインした人だけに表示します。投稿ごとに「コメントを受け付ける」を切り替えられます。投稿者は自分の投稿へのコメントを消せます。通報 → 管理者が投稿・コメントを削除
- **メッセージ**：投稿の「メッセージを送る」から1対1でやり取りできます（1時間60通まで）。ブロックすると、お互いに送れなくなります
- **釣果の提供**：アプリを初めて開いたときに「釣果データの提供のお願い」を表示し、同意した端末の釣果（位置・日時・魚種・締め方・気象・メモなど。写真は除く）をサーバーに送ります。送るのはログイン中だけです（有償アプリとしてログインを前提にする予定のため）。「釣果一覧」の下の設定でいつでもやめられ、やめるとその端末から送った記録は消えます

これらのチェックはアプリの画面だけでなくサーバー側（schema.sql）でも必ず行うので、画面を細工しても通りません。

### 設定の手順（最初に1回）

1. **プロジェクトを作る**
   https://supabase.com でアカウントを作り、New project。リージョンは Northeast Asia (Tokyo) を選びます。

2. **テーブルなどを作る**
   左メニュー SQL Editor → New query に `supabase/schema.sql` の中身を全部貼り付けて Run。
   エラーが出なければ完了です（何度実行しても大丈夫です）。

3. **ログイン後に戻ってくるURLを登録する**
   Authentication → URL Configuration
   - Site URL：`https://<ユーザー名>.github.io/<リポジトリ名>/`
   - Redirect URLs に、上のURLと `http://localhost:8000/` を追加

4. **ログインのメールに6桁コードを入れる**
   Authentication → Emails → Templates → Magic Link の本文に `{{ .Token }}` を追加します。例：

   ```
   <h2>釣果海図ログ ログイン</h2>
   <p>コード：<b>{{ .Token }}</b></p>
   <p>または <a href="{{ .ConfirmationURL }}">ここを押してログイン</a></p>
   ```

   スマホではメールのリンクが別のブラウザで開くことがあるので、コード入力も使えるようにしておきます。

5. **メールの送信元を設定する（ほかの人に使ってもらう前に必須）**
   Supabase 標準のメール送信は、このプロジェクトのチームに入っている人のアドレスにしか届かず、1時間に2通までです。
   自分だけで試す間はそのままで動きますが、ほかの人がログインするには Authentication の SMTP 設定で、自分のメール送信サービス（Brevo、Resend など）を登録してください。

6. **アプリに接続先を書く**
   Settings → API Keys で、Project URL と Publishable key（古いプロジェクトでは anon key）をコピーし、`index.html` の次の2行に貼ります。

   ```js
   const SB_URL = "https://xxxxxxxx.supabase.co";
   const SB_KEY = "sb_publishable_xxxxxxxx";
   ```

   この鍵は公開してよいものです（アクセスはサーバー側の権限設定で守られています）。
   **secret key や service_role key は絶対に貼らないでください。** 誰でも全データを読み書きできてしまいます。

7. **自分を管理者にする**
   アプリの「おすそわけ」タブで自分のメールでログインし、表示名を登録します。そのあと SQL Editor で次を実行します（メールアドレスは自分のもの）。

   ```sql
   update public.profiles set role = 'admin'
    where id = (select id from auth.users where email = 'you@example.com');
   ```

   アプリを開き直すと「管理」ボタンが出ます。

8. GitHub Desktop でコミット → Push。

### 電話番号（SMS）の認証を使うとき

SMSの料金は運営者（Twilio の契約者）が払います。テストの間は無料でできます。

1. **Twilio に登録**（https://www.twilio.com 、無料体験はカード不要・30日間）
   - Console で **Account SID** と **Auth Token** を控える
   - Verify → Services → Create で サービスを作り、**Service SID**（VA で始まる）を控える
   - 無料体験では、登録した番号（最大5つ。登録に使った自分の番号は自動で入る）にだけ送れます。Verify は40回まで無料
2. **Supabase に設定**：Authentication → Sign In / Providers → **Phone** をオンにし、SMS provider に **Twilio Verify** を選んで、上の3つを入れて Save
3. **テスト用の番号**（SMSを送らない・無料）：同じ画面の「Test Phone Numbers and OTPs」に `819000000001=123456` のように入れ、「Test OTPs Valid Until」を決めて Save。**公開前に必ず消す**
4. **送信回数の上限**：Authentication → Rate Limits で、SMSの1時間あたりの上限を低め（例：30）にしておく
5. 自分のスマホで、アプリの「プロフィール」→「認証する」から実際に認証できることを確かめる
6. 「管理」→「電話番号（SMS）の認証」のスイッチをオンにする
7. 本番で使うときは Twilio をアップグレードし、残高を先に入れる方式（自動チャージなし）にしておくと、使いすぎを防げます

### 管理者の仕事

- **利用状況**：「管理」の一番上に、利用者数・ログイン・出品・申し込み・メッセージの件数、直近30日の出品数、よく出品される魚種が出ます
- **やり取りの確認**：「最近のやり取り（全体）」から、他人同士のメッセージも閲覧できます（書き込みはできません）
- **提供された釣果**：一覧・地図・CSVで確認できます。送った人の表示名で出ます

- **会員の管理**：「利用者と会員」で、表示名・メールで絞り込み、「1年間の会員にする／延ばす」「会員を外す」「利用を停止」ができます
- **投稿の通報**：「投稿を見る」で確認し、投稿の削除やコメントの削除。済んだら「対応済みにする」
- **お店の審査**：「管理」→ お店の審査。許可証の写真と許可番号を見て「承認」か「差し戻し（理由つき）」。必要なら保健所の営業許可の公表情報と照合してください
- **通報**：「出品を見る」で釣った位置まで確認でき、出品の削除・出品者の利用停止ができます。済んだら「対応済みにする」
- **出品できない種類**：「管理」の一番下で言葉を追加・削除できます。富山県の漁業調整規則でタコの扱いなどが確認できたら、ここで外してください
- 件数の上限（1日5件・1か月4件）や受付期限を変えるときは、schema.sql の `listings_before_insert` の数字を直して SQL Editor で実行し直します

### schema.sql を更新したとき

新しい schema.sql を受け取ったら、SQL Editor に**全文を貼り直して Run** してください。確認の画面が出たら **「Run without RLS」** を選びます（「Run and enable RLS」は SQL が壊れます）。すでにあるデータは消えず、足りない部分だけが追加・更新されます。

### 管理者が見られる範囲（利用者に知らせておくこと）

- 出品の内容と写真、出品者が釣った位置、申し込み、やり取りのメッセージ、メールアドレスと表示名
- 「みんな」の投稿は誰でも見られます（写真は公開の保存場所に置きます）。1対1のメッセージは、アプリの画面では本人どうしだけが読めます。トラブル対応のため、管理者はデータベース（Supabase の Table Editor）で読むことができます
- 提供に同意した端末の釣果の記録
- 「提供しない」を選んだ端末の記録は見られません

プライバシーポリシーには、集める項目（釣果の位置・日時など）、使いみち（分析とアプリの改善）、公開しないこと、やめ方を必ず書いてください。

### 公開前に確認しておくこと

- 有償の取引（お店向け）について、富山県の保健所（食品衛生）と水産漁港課（漁業調整規則）に、このアプリの流れを説明して確認する
- 利用規約とプライバシーポリシー（メールアドレス・表示名・写真・位置の扱い）を用意し、アプリからリンクする

## データの出典と注意

- 水深: GEBCO Compilation Group (2026) GEBCO 2026 Grid（パブリックドメイン。出典表示が条件）
- 地図: 国土地理院 地理院タイル / 航路標識: OpenSeaMap
- 気象・波浪・潮位: Open-Meteo（モデル値）
- 等深線・推定水深は約400m格子からの参考値です。航海には使えません。
- 記録はブラウザ内（IndexedDB）に保存されます。サイトのURLが変わると別の保存領域になるので、移行時はJSONバックアップ→復元を使ってください。
- 出品・投稿した写真と内容、提供に同意した釣果の記録が Supabase に送られます。そのほかの釣果の記録は端末の中だけです。
