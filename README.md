# 釣果海図ログ

海図（地理院タイル＋OpenSeaMap航路標識）の上に、釣果（位置・魚種・棚・締め方・気象・潮汐・波浪）を記録するWebアプリです。
等深線と推定水深は GEBCO_2026 Grid から作っています（日本周辺、1度×1度の区画ごと）。
「おすそわけ」タブでは、釣りすぎた魚を無料で譲る相手や、魚介類販売業の許可を持つお店とつながれます（富山県内のみ・Supabase を使用）。
「みんな」タブでは、会員が登録した釣果が「新着の釣果」として並び、釣った魚や料理の写真・ブログと合わせて、いいね・コメント・メッセージでやり取りできます。魚の名前で、その魚が釣れた場所を地図で探せます（会員）。

- 会員になるには、右上の名前のボタン →「会員・お支払い・紹介…」から申し込みます（月150円。はじめての申し込みは最初の2か月が無料で、カードの登録が必要です。くわしくは下の「会員のお支払いと紹介」）。管理者が「管理」→「利用者と会員」で「1年間の会員にする」を押しても会員になれます（期限の翌日から無料の扱いに戻ります）
- 会員でなくなっても（支払いが止まった・解約した）、ログインのまま、これまでの釣果と航跡を「釣果一覧」「航跡」で見られ、バックアップもできます。前に会員だった人は、サーバーの記録の取り込み（見るだけ）も続きます。記録の追加・変更と送信は止まります
- 「みんな」の投稿の釣った位置は、会員だけが見られます（投稿した本人は自分の分を見られます）
- **地図の「見る／登録」**：地図の左上で切り替えます。「見る」では、釣果のマークを触ると記録（写真・日時・大きさ・締め・気象など）が開き、何もない所を触ると緯度経度と水深だけが出ます。「登録」では、何もない所を触ると「ここで釣果を登録」が出ます。「釣果を登録」タブを開いている間は、どちらでも地図を触った所が釣った位置になります
- **編集画面で位置を直す**：「釣果一覧」の「編集」や記録の「記録を直す」で開いた画面でも、地図のピン（「つまんで動かす」）をつまんでずらせます。地図を触った所へも動かせます（元のマークの上を触っても、触った所になります）。元の位置からの距離が出て、「元の位置に戻す」で戻せます。スマホでは「地図で位置を直す」で地図が大きくなります。「保存」で確定します
- **指でも点を触りやすく**：スマホでは地図の点を少し大きくし、点から約30px以内を触ればその記録が開きます（PCは約12px）。点が重なっている所では「近くの釣果」の一覧が出て、選んで開けます。「登録」モードで点の近くを触ったときは、一覧の上に「ここで釣果を登録」も出ます
- **位置を直す**：マークを触って開いた記録の「位置を直す」を押すと、マークがピンに変わります。ピンをつまんで動かすか、地図を触った所へ動かし、「この位置に保存」で確定します（元の位置からの距離と推定水深が出ます。スマホでは地図が大きくなります）。直した位置は同期・新着にも反映されます
- **新着の釣果（みんな）**：会員が「釣果を登録」で保存すると、「みんな」→「新着の釣果」に、写真・魚種・大きさ・匹数・釣法・締め方・釣った日時・県と、投稿者のアイコン・表示名が並びます（ここまでは誰でも見られます）。**会員には、釣った位置と、棚・水深・仕掛け・ポイント名・気象・潮・メモなど記録のすべてを公開します。** 登録画面の「みんなの新着に載せる」で、記録ごとに外せます。
- **これまでの釣果の掲載（1回だけ）**：この版にしてから会員がはじめてログインしたとき、それまでに登録した釣果（サンプルを除く）を自動で新着に載せます（端末ごとに1回。進み具合は「釣果一覧」の下に出ます）。1日以上前の釣果は、新着の先頭ではなく釣った日時の順に並びます。すでに載せていた分も、位置とくわしい記録を付けて送り直します
- **釣果を消したとき**：「釣果一覧」で消した釣果は、新着からも必ず消えます（写真も消します）。電波がないときは次にログインしたときに消し、ほかの端末で消した分もサーバー側（同期の「消した」印）で新着から消えます。会員でなくなっても、ログインしていれば自分の釣果は新着から外せ、「消した」印も送られます（ほかの端末の同じ記録も、会員に戻って同期したときに消えます）
- **サンプル（例）の釣果**：はじめて開いたときに入れていた「例」の釣果はなくしました。前の版で入ったサンプルも、開いたときに自動で消えます
- **新着から外れた記録を見るには**：新着は新しい順に並ぶだけで、古くなった釣果も消えません。「もっと見る」でさかのぼるほか、「条件で探す」（魚の名前・地域・期間・毎年の何月か・地図の範囲）、釣果を開いて「この人の釣果」（その人の公開中の釣果の一覧）、会員の「★ お気に入り」で見返せます。投稿した本人が「新着から外す」で外したものと、管理者が削除したものは、誰からも（お気に入りからも）見えなくなります
- **お気に入り（会員）**：釣果や投稿を開いて「☆ お気に入り」を押すと、「新着の釣果」→「★ お気に入り」に保存されます（本人だけが見られます）
- **釣果一覧の写真**：一覧の右に小さい写真を出します。この端末で撮った写真は、表示するときに端末の中で小さくするだけで、サーバーは使いません。ほかの端末で撮った写真（新着に載せた分）は、サーバーの小さい写真（約20KB）を表示します。写真の同期だけでサーバーにある写真は「☁」で表示します
- **ほかの端末で撮った写真**：写真は撮った端末の中にだけ保存され、ほかの端末には「写真の同期」を押したときだけ届きます。地図で開く記録の写真と出品の写真は、この端末に写真がなければ、新着に載せた写真（なければ写真の同期の写真）をサーバーから表示します。出品では、選んだときにサーバーからこの端末に取り込みます
- **別のアカウントでログインするとき**：「おすそわけ」タブの下の「ログアウト」でログアウトしてから、別のメールアドレスでログインします。釣果と航跡はブラウザの中に保存されていてアカウントごとに分かれていないため、前のアカウントの記録が残っている端末でログインすると、同期・提供・新着への掲載を止めて「このアカウントの記録に切り替える」かを聞きます（切り替えると、今の記録をバックアップに保存して端末から消し、このアカウントの記録をサーバーから取り込みます）。2つのアカウントを同時に使うときは、シークレットウィンドウか別のブラウザを使ってください
- **サーバーの使用量**：管理者は「おすそわけ」→「管理」の「サーバーの使用量」で、データベースの大きさ、写真などのファイルの容量（保存場所ごと）、大きい表を見られます。通信量は Supabase の画面（Organization → Usage）で見ます
- **会員だけの機能の表示**：会員でない人には、会員だけの機能（釣果を登録・航跡・おすそわけ・＋登録・投稿・お気に入り・地図の「登録」など）を薄く🔒付きで表示します。押すと、会員になると使える機能の一覧が出ます
- 一覧の写真は小さい写真（320px）を使い、通信量を抑えます（新着に載せるとき、元の写真と一緒に置きます）いいね（一覧からも押せます）・コメント・通報・メッセージは、写真・ブログの投稿と同じです。自分の釣果は、開いて「新着から外す」で外せます
- **県の優先**：新着は「先に表示する県」で選んだ県の釣果を先に、新しい順に並べます。選んでいないときは、プロフィールの「住んでいる県」（右上の名前のボタン）を使います。釣った場所の県は、陸・港・川では国土地理院の住所検索から、海の上は一番近い県（120km以内）を自動で入れ、登録画面で直せます
- **条件で探す**：「新着の釣果」→「条件で探す」で、魚の名前（空なら全部の魚。ひらがな・別名の一部でも可。例：「あこう」でキジハタ（アコウ））・地域（県）・期間（7日〜1年／日付を指定）・時期（毎年の何月）・地図に見えている範囲（会員）で、新着に載ったすべての釣果から探します。結果には魚種別・県別の数が出て、会員には釣れた場所を地図に出します。会員でない人には件数と県別の数だけが出ます
- 「みんな」タブの数字は、メッセージの未読と、先に表示する県の新着の数の合計です
- 地図の上の中央に現在地の緯度経度（度分表示と精度 ±m）を出します。押すとその場所へ移動します。GPSのないPCでは数kmずれます
- 右上の自分の名前のボタンから、アイコン（正方形に切り抜いて256px）と表示名を変えられます。アイコンがない人は表示名の1文字目を丸で表示します（avatars バケット・誰でも見られる）
- 航跡：線の色と太さを選べます。色は途中で変えると、それ以降の線だけが変わり、記録済みの色は残ります（区間ごとにまとめて変えることもできます）。アプリを閉じていたなどで2分以上記録が途切れた区間は点線で表示します
- 航跡の線の色は「色の決め方…」で「日ごとに自動（8色を自分で決められる）」か「いつも同じ色」を選べます。変えても記録済みの航跡の色は変わりません
- **PCとスマホの同期（会員）**：ログイン中は、釣果（写真は除く）と航跡を自動で同期します（開いたとき・保存したとき・裏に回したとき）。同じ記録を両方で直したときは、あとから直した方が残ります。消した記録はほかの端末でも消えます。写真は「釣果一覧」の下の「写真の同期…」から「写真を送る・取り込む」を押したときだけ送り・取り込みます（本人だけが見られる cloud バケット）
- 会員でない端末やログインしていない端末では、これまでどおり「JSONバックアップ」→もう一方で「復元」で移せます
- メッセージは、投稿を開いて「メッセージを送る」から始めます。やり取りは「みんな」→「メッセージ」に並びます

## 削除した釣果を戻す・変更を戻す

- **削除した釣果を戻す**：「釣果一覧」の下の「削除した釣果を戻す…」から「元に戻す」。戻した釣果は、ほかの端末と新着にも戻ります。出てくるのは次の3つです
  - この端末で消した分：写真ごと30日とっておきます
  - サーバーの同期にとってある分（会員）：期限なし。ほかの端末で消した分も出ます。写真は「別の端末の写真を取り込む」で戻せることがあります
  - 削除をとっておく仕組みを入れる前に消えた分：運営者に提供された釣果に残っていれば、そこから戻します（ログインしていれば会員でなくても出ます）
- **変更を戻す（元に戻す）**：記録の編集画面の「変更を戻す…」か、地図の記録の吹き出しの「変更を戻す」。前の状態の一覧から「この状態に戻す」を押すと、その時の記録に戻ります（今と違うところも表示）。戻す前の状態も履歴に残るので、戻しすぎてもまた戻せます。戻した内容はほかの端末と新着にも反映します
  - この端末の履歴：直した回数で10回分を90日。写真も戻せます。位置を直した・同期でほかの端末の変更が入った、も1回に数えます
  - サーバーの履歴（会員）：10回分。ほかの端末で直した分も戻せます。写真は今のままにします（写真はこの端末の履歴で戻します）
  - この機能を入れる前（版 2026.11.02.14 より前）の変更は残っていません
- **バックアップ（JSON）から戻す**：「復元（JSON）」でファイルを選ぶと、消えていた釣果を新しい変更として戻します（ほかの端末と新着にも戻ります）。この端末の方が新しい釣果は、そのままにします
- **削除の確認**：「削除」を押すと確認の画面が出ます（2回続けて触っても消えません）
- **サーバーから全部取り込み直す**：「釣果一覧」の下（会員）。サーバーの同期には残っているのに、この端末にない釣果を取り込みます
- **いつ・どうやって消えたか調べる（管理者）**：`tools/diagnose_deleted.sql` を SQL Editor で実行すると、その魚種の記録がサーバーのどこに残っているか（同期・運営者に提供された釣果・新着）と、削除の印が付いた日時が分かります。削除の印は「釣果一覧」の「削除」を押したときにだけ付きます（端末の時刻と、サーバーに届いた時刻）。削除の印がなければ、その端末の中だけで消えています（ブラウザのデータが消えた、アカウントの切り替えなど）
- **提供された釣果から戻す（管理者）**：ふつうは「削除した釣果を戻す」で戻せます。SQL で戻すときは `tools/restore_from_shared.sql` の番号を書き換えて実行します（写真は戻りません。持ち主が会員のとき）
- バックアップ（JSON）のファイルがあれば、そこからも戻せます（「このアカウントの記録に切り替える」を押したときにも、ダウンロードフォルダに「釣果バックアップ_日付.json」が保存されています）。まだ同期していない別の端末に残っていれば、その端末を機内モードにしてから開き、「バックアップ（JSON）」で保存してから戻してください（電波があると、開いたときに同期で消えてしまいます）

## おすそわけの本人の確かめ（カード）

- 電話番号（SMS）の確認は、2026年11月にやめました。電話番号は預かりません（前に預かった番号は、schema.sql を実行すると消えます）
- 代わりに、会員の申し込みで Stripe に登録したカードを使います。受け取るのは、カードの種類（クレジット・デビット・プリペイド）と、同じカードかどうかだけが分かる番号（Stripe の「指紋」）で、カード番号は受け取りません
- **無料期間は1枚のカードにつき1回**：ほかのアカウントですでに無料期間を使ったカードや、プリペイド式のカードで申し込むと、無料期間は付かずにすぐお支払いになります
- **利用を停止した人**：管理者が「利用を停止」を押すと、その人の会員の支払いも Stripe ですぐ止め、そのカードに印を付けます。同じカードで別のアカウントを作って申し込んでも、すぐ止まります
- **新しいアカウントの制限**：登録して14日間は、おすそわけの出品は1日1件・お店向けは1件、申し込みは同時に2件までです
- **管理者の設定**：「管理」の「おすそわけの本人の確かめ」をオンにすると、おすそわけの出品・申し込みは、カードを登録した会員だけになります（管理者が「1年間の会員にする」で会員にした人はカードがないので使えなくなります）。初めはオフです
- 「管理」→「会員の支払いと紹介」に、カードの種類・同じカードを使っているほかのアカウント・停止のカードかどうかが出ます
- Supabase の「Authentication」→「Sign In / Providers」の Phone と、Twilio は、もう使っていないので止めてかまいません

## サーバーの安全点検（2026年11月8日）

Supabase の自動点検（Advisors → Security）の指摘に対応しました（schema.sql の 14.）。
- 関数が使う場所（search_path）を固定
- トリガーの関数を、画面（API）からは呼べないように
- ブロックの有無を調べる関数を、外から呼べないように
- 使用量の関数を、ログインした人だけに
残っている指摘は、わざとそう作っているものです。
- user_cards（auth.users を使う）：管理者だけが見る画面用で、ログインしていない人は読めず、管理者以外のログインした人には0件
- security definer の表示用ビュー：中で見せてよい行と列だけに絞っています（会員でない人・ログインしていない人には、新着の釣った位置と詳細は見えません。確認済み）
- app_secrets：だれも直接読めないようにしています
- ログインした人が呼べる関数：中で本人か管理者かを確かめています
- 漏えいしたパスワードの確認：このアプリはパスワードを使わないので関係ありません

## 会員のお支払いと紹介（Stripe）

### しくみ

- **料金**：月150円（自動で更新）。はじめての申し込みは、最初の2か月（1＋1か月）が無料です。申し込みにはカードの登録が必要で、無料期間が終わると自動でお支払いに移ります（無料期間中に解約すれば料金はかかりません）。無料期間は1人1回です
- **申し込み・解約**：右上の名前のボタン →「会員・お支払い・紹介…」。「会員になる」で Stripe の支払い画面が開きます。カードの変更・解約・領収書は「支払い方法の変更・解約」から（Stripe の画面）。カードの番号はこのアプリにもサーバーにも残りません
- **支払いができなかったとき**：すぐ会員から外れ、ログイン（無料）の扱いに戻ります。ただし、これまでの釣果・航跡は「釣果一覧」「航跡」で見られ、サーバーの記録も取り込めます（見るだけ）。カードを直して支払いが済むと、すぐ会員に戻ります
- **紹介**：「会員・お支払い・紹介…」に自分の紹介コードと紹介のリンクがあります。リンクから来た人は自動で、またはコードを入れて（申し込みの前だけ・1回だけ）紹介した人を登録します
  - 紹介した人が無料期間のあと**初めて実際に支払う**と、紹介者の料金が1か月無料になります（Stripe の残高に1か月分を足し、次の請求から引きます。1人につき1回）。紹介者がまだ申し込んでいなければ、申し込んだときに使われます
  - **つ抜け会員**：紹介した人のうち、支払い中の会員が10人以上いる間は、紹介者の料金が無料になり、アイコンの右下に「つ」の印が付きます（新着・投稿・コメント・メッセージ・プロフィール）。9人以下になると、次の請求から有料に戻り、印も外れます
  - 数えるのは**直接紹介した人だけ**で、特典はこのアプリの料金の割引だけです（お金の支払いはしません）
  - 何段もさかのぼって数える仕組みや、お金で報酬を払う仕組み（キックバック）は入れていません。Stripe の禁止業種（勧誘にもとづいて報酬を払うマルチレベルマーケティング）と、特定商取引法の連鎖販売取引にあたるおそれがあるためです
- **特定商取引法に基づく表記**：会員の案内と「会員・お支払い・紹介」の下にリンクがあります。管理者が「管理」→「会員の支払いと紹介」→「特定商取引法に基づく表記を書く」で書きます（ひな形が入っています。［ ］の中を書き換えてください）。Stripe の審査でも、このページが見られることが必要です
- **管理者**：「管理」→「会員の支払いと紹介」に、申し込んだ人の状態・次の日付・紹介した人数・支払い中の人数・もらった特典が出ます
- 金額や「10人」の数は、Stripe の価格と、サーバーの設定（app_settings の price_month・tsunuke_n）で変えられます

## 写真の変え方・消し方（操作手順）

写真そのものは、撮った・選んだ端末の中に保存されます。どの写真が最新かの目印（と変えた日時）は記録と一緒に同期され、新着の写真もサーバーがその日時で確かめるので、古い写真で上書きされることはありません。

**写真を差し替える**
1. どの端末でも「釣果一覧」→「編集」（または地図で記録を開いて「記録を直す」）
2. 古い写真の「×」で外し、「写真を撮る・選ぶ」で新しい写真を足す
3. 「変更を保存」。この端末の写真が「最新の写真」になります
4. 新着に載せている釣果は、電波のよいところで数秒アプリを開いたままにすると新着の写真も変わります（「反映待ち」と出たら、送れるまで自動でくり返します）
5. ほかの端末は、開いたとき（同期のとき）から新しい写真を表示します

**写真を消す**
- 写真がこの端末にあるとき：「×」で全部外して「変更を保存」
- 写真がこの端末にないとき（ほかの端末で撮った写真）：編集画面の「写真を外す（どの端末でも写真なしにする）」→「変更を保存」
- 新着の写真も消え、ほかの端末でも表示されなくなります（ほかの端末に残っている古い写真のデータは、表示も送信もされません）

- 前の版で載せた新着の写真・写真の同期の写真には目印がないため、記録を開いたときに一度だけ写真を読み込んで中身を比べます（結果は端末に覚えておくので、次からは読み込みません）。同じ写真なら「端末によって写真が違います」は出ません

**別の端末の写真を足す**
- 編集画面の「写真を撮る・選ぶ」の横の「別の端末の写真を取り込む」で、この記録についてほかの端末から新着に載せた写真・「写真の同期」で送った写真のうち、まだ入っていない写真を足せます（同じ写真は二重に入りません）。「変更を保存」で確定します。ボタンは写真のない釣果を含め、記録の編集画面にいつも出ます（新しく登録する画面には出ません）。取り込める写真がまだサーバーにないときは、その手順が出ます

**新着の写真が変わらないとき**
- 地図で記録を開き「写真の状態を調べる」→「新着への最後の送信」に、最後に送った日時と結果（写真○枚・写真はそのまま・送れなかった理由）が出ます。「新着に送り直す」でその場で送り直せます

**ほかの端末の写真を、この端末に入れたいとき**
- 新着に載せている釣果：編集画面の「写真をこの端末に取り込む」
- 新着に載せていない釣果：写真がある端末で「釣果一覧」→「写真の同期…」→「写真を送る」、こちらの端末で同じボタン→「写真を取り込む」

**前の版で差し替えた記録で、端末ごとに写真が違うとき**
- 「最新の写真」の目印が入る前（2026.11.02.3 より前）に差し替えた記録は、どの端末の写真が新しいか分からないため、それぞれの端末の写真が出ます
- 端末によって写真が違うと、地図で開いた記録と編集画面に「この端末の写真を最新にする」「新着に載っている写真にそろえる」「写真の同期の写真にそろえる」が出ます。正しい写真を選ぶと、すべての端末と新着がその写真になります（地図の記録からはその場で保存、編集画面では「変更を保存」で確定）。以前の説明：正しい写真が出ている端末で「編集」→「この端末の写真を最新にする」→「変更を保存」。正しい写真がその端末にないときは、「新着に載っている写真にそろえる」または「写真の同期の写真にそろえる」→「変更を保存」でも直せます。新着の写真がその写真になり、ほかの端末でも（サーバーから）その写真が出ます
- ほかの端末に写真そのものも入れたいときは、その端末で「編集」→「写真をこの端末に取り込む」

- 目印のない（前の版の）記録でも、新着に「最新の写真」として目印つきで載っている写真がこの端末の写真と違えば、新着の写真を表示します。目印のない端末からは、新着にすでに写真があるとき写真を送りません
- 地図で記録を開いたときの「写真の状態を調べる」に、表示している写真・この端末の写真・最新の写真の目印・新着の写真・写真の同期・同期の状態が出ます。写真がうまく表示されないときは、この画面を見せてください

**同期での写真の目印の扱い**
- 記録の同期は「あとから直した端末の記録」を残しますが、写真の目印（最新の写真がどれか）だけは別に「写真を変えた日時」が新しい方を残します（端末でもサーバーでも）。ほかの項目をあとから別の端末で直しても、写真の差し替えは消えません
- 「釣果一覧」の下に、最後に同期した時刻が出ます。同期が止まっているとき（この端末に別のアカウントの記録があるときなど）は、その理由と「どうするか選ぶ」ボタンが出ます

**更新ボタン**
- 画面の右上の「↻ 更新」で、送れていない記録・写真を送ってから、最新の版で開き直します。メールのアプリの中で開いたときなど、ブラウザの再読み込みボタンがない画面で使ってください
- メールのリンクをメールのアプリの中で開くと、ふだんのブラウザとは別の保存場所になり、端末の釣果が見えません。ふだんのブラウザでアプリを開き、メールに書かれた6桁のコードでログインするのがおすすめです

**一覧・地図の写真の見え方**
| 表示 | 意味 |
|---|---|
| 写真 | この端末の写真が最新（または新着に載っている最新の写真をサーバーから表示） |
| ☁ 写真○枚 | 最新の写真が「写真の同期」にある（「写真の同期…」で取り込めます） |
| 写真は ほかの端末 | 最新の写真は、写真を変えた端末にだけある（その端末でアプリを開くと新着に送られます） |
| （なし） | 写真なし（どこかの端末で外した） |

**アプリの版**
- 右上の名前 → プロフィールの下に「アプリの版」が出ます。どの端末も同じ版で使ってください
- サーバー（schema.sql）がより新しい版を求めているときは、画面の上に「読み込み直してください」と出ます。押すと最新の版になります（GitHub Pages は更新から最大10分ほど古い版を返すことがあります）
- 古い版の画面から写真を送っても、サーバーが断るので新着の写真は戻りません

## おすそわけ・お店の機能（Supabase）

設定しなくても釣果の記録・航跡・等深線はこれまでどおり使えます。「おすそわけ」タブだけが「設定が必要です」と表示されます。

### しくみ

- **おすそわけ**：無料。取りに来てもらう対面渡しだけ。受付は釣った日のうち。1人1日5件まで
- **お店向け**：魚介類販売業の許可を持ち、管理者が承認したお店だけが見られ、申し込めます。支払いはアプリを通さず当事者間。1人1か月4件まで
- 出品は「24時間以内に写真つきで記録した自分の釣果」から選ぶ形だけ。釣った位置は本人と管理者だけが見られ、ほかの人には受け渡し場所が約1km単位で表示されます
- アワビ・ナマコ・サザエ・イセエビ・ウニ・貝・海藻・エビ・カニ・ホタルイカ・タコ・フグなどは出品できません（管理画面で追加・削除できます）
- 受け渡し場所と時間は、申し込み後のメッセージで決めます
- **取り消し・取り下げの理由**：申込者の取り消し（受け渡しで魚を見てやめる場合も）と、出品者の取り下げでは理由を選び、相手のやり取りに自動でお知らせが出ます。受けた・見送った・受け渡し完了などもお知らせが出ます。自分で取り消した申し込みは、申し込み直せます
- **連絡先カード**：電話番号・LINE ID・住所・時間帯を「やり取り」の上に保存しておき、申し込みが決まった相手にだけ送れます。相手から見えるのは取引中と、受け渡し済みから3日間だけです
- **お店の買い取り希望**：承認済みのお店が「魚種・サイズ・締め方・処理・価格・地域・期限（60日以内）」を出せます（受付中は10件まで）。釣り人は「探す」で見られ、条件に合うお店向けの出品は、そのお店の「探す」で「希望に合う」と表示され先頭に並びます
- **出品の編集**：受付中の出品は、匹数・大きさ・締め方・締めた日時・処理・保冷・受け渡し場所・価格・ひとことを直せます（魚種・釣った日時・写真・位置は変えられません）。申し込んでいる人には変更のお知らせが届きます
- **締めた日時**：日付つきで入力します。「釣った日時」には開いた時刻が入るので、あとから登録するときは「30分前」「1時間前」などのボタンや写真の撮影日時で直します。締めた日時が釣った日時より前・未来になっていると、その場で知らせて直すボタンを出します
- **相互評価**：受け渡し済みの取引を、30日以内にお互い1回ずつ3項目×5段階で評価します。平均は3件以上たまってから表示します。ひとことは管理者だけが見られ、不当な評価は管理画面から消せます
- **本人の確かめ**：電話番号（SMS）の認証はやめ、会員の申し込みで登録したカードで確かめます（上の「おすそわけの本人の確かめ（カード）」）
- 通報 → 管理者が出品の削除・利用停止
- **新着の釣果**：会員の釣果を posts（kind = 'catch'）に1件ずつ載せます。くわしい記録は detail 列に入れ、post_cards で会員と本人にだけ見せます。同じ記録は1件にまとめ、直すと上書き・記録を消すと新着からも消えます。1日200件まで（これまでの釣果をまとめて載せるときは数えません）。お気に入りは post_favorites（本人だけ）。電波がないときは、次にログインしたときに送り直します
- **みんな（写真・ブログ）**：写真は6枚まで、1日20件まで。釣果の記録を選ぶと魚種・大きさ・写真が入ります。「釣った位置を載せる」を選んだときだけ位置を保存し、ログインした人だけに表示します。投稿ごとに「コメントを受け付ける」を切り替えられます。投稿者は自分の投稿へのコメントを消せます。通報 → 管理者が投稿・コメントを削除
- **メッセージ**：投稿の「メッセージを送る」から1対1でやり取りできます（1時間60通まで）。ブロックすると、お互いに送れなくなります
- **釣果の提供**：はじめてログインしたときの確認事項（表示名の登録と一緒に出る同意の項目）に「記録した釣果は運営者に送られます」を入れてあり、同意しないと使い始められません。同意した会員の釣果（位置・日時・魚種・締め方・気象・メモなど。写真は除く）を、ログイン中にサーバーへ送ります。個別にオン・オフするスイッチや別の案内はありません

これらのチェックはアプリの画面だけでなくサーバー側（schema.sql）でも必ず行うので、画面を細工しても通りません。

### 設定の手順（最初に1回）

1. **プロジェクトを作る**
   https://supabase.com でアカウントを作り、New project。リージョンは Northeast Asia (Tokyo) を選びます。

2. **テーブルなどを作る**
   左メニュー SQL Editor → New query に `supabase/schema.sql` の中身を全部貼り付けて Run。
   エラーが出なければ完了です（何度実行しても大丈夫です）。

3. **ログイン後に戻ってくるURLを登録する**
   Authentication → URL Configuration
   - Site URL：`https://<ユーザー名>.github.io/<リポジトリ名>/`
   - Redirect URLs に、上のURLと `http://localhost:8000/` を追加

4. **ログインのメールに6桁コードを入れる**
   Authentication → Emails → Templates → Magic Link の本文に `{{ .Token }}` を追加します。例：

   ```
   <h2>釣果海図ログ ログイン</h2>
   <p>コード：<b>{{ .Token }}</b></p>
   <p>または <a href="{{ .ConfirmationURL }}">ここを押してログイン</a></p>
   ```

   スマホではメールのリンクが別のブラウザで開くことがあるので、コード入力も使えるようにしておきます。

5. **メールの送信元を設定する（ほかの人に使ってもらう前に必須）**
   Supabase 標準のメール送信は、このプロジェクトのチームに入っている人のアドレスにしか届かず、1時間に2通までです。
   自分だけで試す間はそのままで動きますが、ほかの人がログインするには Authentication の SMTP 設定で、自分のメール送信サービス（Brevo、Resend など）を登録してください。

6. **アプリに接続先を書く**
   Settings → API Keys で、Project URL と Publishable key（古いプロジェクトでは anon key）をコピーし、`index.html` の次の2行に貼ります。

   ```js
   const SB_URL = "https://xxxxxxxx.supabase.co";
   const SB_KEY = "sb_publishable_xxxxxxxx";
   ```

   この鍵は公開してよいものです（アクセスはサーバー側の権限設定で守られています）。
   **secret key や service_role key は絶対に貼らないでください。** 誰でも全データを読み書きできてしまいます。

7. **自分を管理者にする**
   アプリの「おすそわけ」タブで自分のメールでログインし、表示名を登録します。そのあと SQL Editor で次を実行します（メールアドレスは自分のもの）。

   ```sql
   update public.profiles set role = 'admin'
    where id = (select id from auth.users where email = 'you@example.com');
   ```

   アプリを開き直すと「管理」ボタンが出ます。

8. GitHub Desktop でコミット → Push。

### 管理者の仕事

- **利用状況**：「管理」の一番上に、利用者数・ログイン・出品・申し込み・メッセージの件数、直近30日の出品数、よく出品される魚種が出ます
- **やり取りの確認**：「最近のやり取り（全体）」から、他人同士のメッセージも閲覧できます（書き込みはできません）
- **提供された釣果**：一覧・地図・CSVで確認できます。送った人の表示名で出ます

- **会員の管理**：「利用者と会員」で、表示名・メールで絞り込み、「1年間の会員にする／延ばす」「会員を外す」「利用を停止」ができます
- **投稿の通報**：「投稿を見る」で確認し、投稿の削除やコメントの削除。済んだら「対応済みにする」
- **お店の審査**：「管理」→ お店の審査。許可証の写真と許可番号を見て「承認」か「差し戻し（理由つき）」。必要なら保健所の営業許可の公表情報と照合してください
- **通報**：「出品を見る」で釣った位置まで確認でき、出品の削除・出品者の利用停止ができます。済んだら「対応済みにする」
- **出品できない種類**：「管理」の一番下で言葉を追加・削除できます。富山県の漁業調整規則でタコの扱いなどが確認できたら、ここで外してください
- 件数の上限（1日5件・1か月4件）や受付期限を変えるときは、schema.sql の `listings_before_insert` の数字を直して SQL Editor で実行し直します

### schema.sql を更新したとき

新しい schema.sql を受け取ったら、SQL Editor に**全文を貼り直して Run** してください。確認の画面が出たら **「Run without RLS」** を選びます（「Run and enable RLS」は SQL が壊れます）。すでにあるデータは消えず、足りない部分だけが追加・更新されます。

### 管理者が見られる範囲（利用者に知らせておくこと）

- 出品の内容と写真、出品者が釣った位置、申し込み、やり取りのメッセージ、メールアドレスと表示名
- 「新着の釣果」に載せた釣果（写真・魚種・大きさ・匹数・釣法・締め方・釣った日時・県）は誰でも見られます。釣った位置は会員だけが見られます。利用規約・プライバシーポリシーにも書いてください
- 「みんな」の投稿は誰でも見られます（写真は公開の保存場所に置きます）。1対1のメッセージは、アプリの画面では本人どうしだけが読めます。トラブル対応のため、管理者はデータベース（Supabase の Table Editor）で読むことができます
- 会員の釣果の記録（はじめの確認事項で同意済み）
- 「提供しない」を選んだ端末の記録は見られません

プライバシーポリシーには、集める項目（釣果の位置・日時など）、使いみち（分析とアプリの改善）、公開しないこと、やめ方を必ず書いてください。

### 公開前に確認しておくこと

- 有償の取引（お店向け）について、富山県の保健所（食品衛生）と水産漁港課（漁業調整規則）に、このアプリの流れを説明して確認する
- 利用規約とプライバシーポリシー（メールアドレス・表示名・写真・位置の扱い）を用意し、アプリからリンクする

## サーバーの容量の目安（Supabase）

1件の釣果あたり：データベース 約5KB（新着・同期・運営者への提供の3か所）、写真 約220KB×枚数（新着用の元の写真＋小さい写真）。
会員1人が1年に釣果150件・写真1.5枚・航跡40本とすると、データベース 約4MB／年、写真 約50MB／年（写真の同期も使うと約100MB）。

| 会員数 | データベース（1年分） | 写真（1年分） | 通信量（月） | プラン |
|---|---|---|---|---|
| 10人 | 約40MB | 0.5〜1GB | 数GB | 無料（500MB・1GB・5GB）でぎりぎり |
| 100人 | 約0.4GB | 5〜10GB | 15GB前後 | Pro（月25ドル：8GB・100GB・250GB） |
| 500人 | 約2GB | 25〜50GB | 75GB前後 | Pro の範囲内 |
| 3000人 | 約12GB | 150〜300GB | 450GB前後 | Pro＋超過分（月50〜70ドル程度） |

通信量は、会員の多くが毎日「みんな」を見る前提（1日あたり一覧5ページ・記録10件で約5MB）です。無料プランは1週間使われないと止まるので、ほかの人に使ってもらうときは Pro にしてください。

## データの出典と注意

- 水深: GEBCO Compilation Group (2026) GEBCO 2026 Grid（パブリックドメイン。出典表示が条件）
- 地図: 国土地理院 地理院タイル / 航路標識: OpenSeaMap
- 気象・波浪・潮位: Open-Meteo（モデル値）
- 等深線・推定水深は約400m格子からの参考値です。航海には使えません。
- 記録はブラウザ内（IndexedDB）に保存されます。サイトのURLが変わると別の保存領域になるので、移行時はJSONバックアップ→復元を使ってください。
- 出品・投稿した写真と内容、会員としてログインしている端末の釣果の記録（写真は除く）が Supabase に送られます。ログインしていない端末の釣果の記録は端末の中だけです。
